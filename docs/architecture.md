# Architecture and port boundaries

The product consists of `fta2-ce`, its own platform layer and the imported SAGA2 gameplay algorithms. The ScummVM development reference is built separately and is not linked into the product.

| Component | Responsibility |
|---|---|
| `src/main.cpp` | CLI, user paths, data validation and direct game startup |
| `src/platform/startup.*` | Bundled-data discovery, remembered installations and the Windows folder picker |
| `src/platform/resources.*` | SHA-256, HRES bounds checks, the supported DOS profile and deterministic extraction |
| `src/platform/runtime.*` | Standard containers and streams, files, configuration, timers, SDL window/input/palette and PCM mixing |
| `src/platform/saves.*` | Original chunk-format validation and optional native metadata |
| `src/platform/localization.*` | Embedded translation catalogs, presentation-only lookups, language preference and owned localized bitmap fonts |
| `src/saga2/` | Simulation, SAGA bytecode, original UI, inventory, dialogue, magic, combat, maps and software rendering |
| `src/audio/` | Portable XMIDI/Miles algorithms, the Nuked OPL3 chip and a small native MIDI interface |
| `src/platform/probe.*` | Development scenario enabled explicitly by `--smoke-test` |

The platform provides an indexed framebuffer: 640 × 480 by default, or 854 × 480 in the optional widescreen mode. The original renderer writes 8-bit pixels; SDL receives an RGBA texture after palette and cursor application. Nearest-neighbour filtering and letterboxing preserve the active framebuffer aspect ratio. Mouse coordinates use the same SDL logical presentation, including after window resizing and changes in pixel density. Normal simulation uses the original 72 Hz timer. Test mode uses controlled virtual time and seed 42.

The mixer owns the audio callback and converts original PCM data to floating-point stereo at 48 kHz. The XMIDI parser and Miles driver write to Nuked OPL3; music timing advances with generated audio samples. Speech channels retain their distance attenuation separately from the configured speech gain. Mixer synchronization updates that gain under the audio mutex, so an active stream reacts immediately without restarting and without applying the setting twice to new speech. The deterministic mixing hook returns its rendered stereo samples for gain regression checks. The base DOS profile has no usable speech and uses text fallback. Optional verified CD speech is enabled after startup validation; missing, silent or inaudible requests also retain the fallback. The driver uses the original instrument banks. The callback and game thread synchronize mixer/music state through mutexes. Audio does not require a system MIDI synthesizer or DOS drivers.

Saves are written outside the installation, first to a temporary file and then replaced through SDL. The header and all 30 original chunks are preserved, followed by an optional `NRNG` chunk containing a 4-byte little-endian seed. Original saves without this chunk can be loaded. Before destructive restoration, the loader checks the header, chunk bounds, duplicate tags and required chunks. This validation does not make the format a general-purpose secure parser for arbitrary untrusted input.

The infrastructure port replaces `Common::` names with `Native::` and removes inheritance from `Engine`, `OSystem`, the detector, metaengine, plugins and GUI debugger. Native streams and utilities are new implementations based on the standard library. Only selected portable gameplay and audio algorithms remain from ScummVM. The preserved random sequence matches `common/random.cpp` from the pinned revision.

New `MotionTask` instances are value-initialized to make saves reproducible. Cancelled tasks are released after the game step finishes; cancelled pathfinding must not dereference a destroyed owner. The port also fixes resource ownership issues found by sanitizers and handles an empty window list.

The gameplay G shortcut searches only the selected actor's inventory through the original recursive container iterator. For the supported DOS profile, map prototype 320 uses ordinary Inventory class 13 and on-use script 1149; the shortcut schedules `MotionTask::useObject` just like inventory double-click. Original scripts continue to decide whether and where to show the map. Modal input, UI locks and held/dragged objects prevent shortcut activation.

The map modal alone handles arrow-key panning. Screen-horizontal movement changes its two isometric base coordinates in opposite directions; screen-vertical movement changes both together. Each key advances two metatiles per axis, using the existing draw-time world bounds. SDL key repeats continue the movement. Legacy Home/End/Page Up/Page Down, map scripts, party position and shared exploration remain unchanged. Special key codes bypass character case conversion in the UI dispatcher.

## Localization and captured speech

The language modal offers four mutually exclusive radio choices in two rows, with E/C/S/F shortcuts and unchanged confirmation bounds. Per-language font copies preserve explicitly bound endonyms and captured speech; original fonts remain available. NLOC version 1 retains its layout and uses the existing language byte: 1 Czech, 2 Spanish, 3 French. Loading a save never changes the user preference.

The platform localization service accepts native UI literals, original NAME indices and original script segment/table/index keys through separate interfaces. UTF-8 catalogs under `localization/` are compiled to an embedded sorted, language-qualified table (Windows-1250 for Czech, Windows-1252 for Spanish/French) using Python's standard library. Each game entry is checked against the SHA-256 of the exact original bytes. Missing or stale entries return the original and emit a bounded English diagnostic. Preserved entries reference the user's original data instead of embedding original strings. The interpreter's `strAddress`, object lookup by name, resource identifiers and technical logs retain the original strings. Translation is applied only at display formatting boundaries, including `%n` names and `%s` script strings; formatting arguments and choice/image/page markers retain their order.

`language=en|cs|es|fr` belongs to the user configuration. Options has a Language button at (214,206), below the game clock checkbox; its independent modal commits an accepted selection immediately after destroying the Language window, while Options stays open. Options owns caption refresh bindings with copies of source literals and original fonts; Apply updates them in place without rebuilding controls or resetting sliders. The shared localized-interface refresh updates status messages, tooltips, names and owner markers. Closing Options discards the pre-switch saved framebuffer and redraws instead of restoring old-language pixels. The other Options preferences also apply without closing the window. Entering any translated language enables subtitles, while later user changes to that preference remain available. Control labels, actor state text, hovered/held-item text, owner initials and name plaques are refreshed through the normal redraw path. Speech assembled before a switch retains its captured language. English CD voice identifiers and decoding never depend on translated text.

Localized fonts are owned memory copies of the original bitmap fonts, with Czech Windows-1250 or Western Windows-1252 glyph recipes appended to their pixel data and metrics. Original English fonts and source resources remain available. Cached font copies are released before executable resources. Rendering indexes glyph metrics using unsigned bytes. Fixed controls check actual glyph widths and outlined/shadow ink height at the original font size. Speech checks its assembled block including choices, and documents check buffers, page/line capacities and actual rendered lines. Overflow increments a diagnostic counter; localization integration requires zero. Runtime checks and extracted catalog coverage do not prove that every story branch has been exercised or linguistically reviewed.

Portrait names are embedded artwork rather than font text. Czech Julián/Filip plaques compose the original bold letter pixels from BTN 8/9 in memory, with an acute accent and F derived from the original strokes, retaining the foreground/shadow palette. Clear textured edge pixels cover the entire old lettering and shadow; English/Spanish/French and the Czech Kevin plaque keep the original images. No recovered glyph or background assets are shipped. Credits are generated by script 110 using table `script:86:2:*`; role fragments are localized while author names, company/game titles and licensing text are retained. Localization integration explicitly includes this script and captures all its page spreads in all four languages and every aspect/sidebar combination.

Original speech text and its timing remain in the unchanged `SPCH` chunk. When translated speech is pending, an optional `NLOC` chunk after the original chunks captures its display text. All fields are little endian: `u16 version=1`, `u16 record_count`, then records with `u16 speech_ordinal`, `u8 language` (1 Czech, 2 Spanish, 3 French), `u8 reserved=0`, 64 ASCII hex bytes of SHA-256 over the canonical speech bytes, `u16 display_length`, and that many bytes in the captured language's encoding without a terminator. Ordinals match `SPCH`: active list followed by inactive list. The validator checks chunk bounds, ordinals, duplicates, hashes, choice counts, NUL absence and an 8,192-byte display limit before destructive restoration. Canonical speech retains its original 512-byte capacity. Saves without `NLOC` restore pending speech in English. The loader continues beyond `CONT` to read optional native chunks, skipping unknown chunks; neither `NLOC` nor `NRNG` changes the global language preference. Captured speech images are released during cleanup/load as well as normal disposal.

See [catalog workflow, draft status and translation provenance](../localization/README.md). Complete localization release acceptance requires reviewed display text, all relevant layout checks and linguistic/visual review; draft entries deliberately fail the catalog completeness audit.

## Optional original CD speech

`--voice-file PATH` explicitly selects an optional English CD `FTAVOICE.HRS`. Otherwise startup checks `media/FTAVOICE.HRS` beside the data directory, followed by the data directory itself. The 15,042-byte fake DOS archive is ignored. The real archive is pinned by size and SHA-256 after HRES bounds validation; it contains one TALK group with 4,320 mono signed little-endian 16-bit Shorten v1 recordings at 22,050 Hz. All five shared CD archives are identical to the supported DOS profile; no Windows executable or executable offsets are used. The voice archive is opened read-only and is not extracted into the user's resource cache.

The native adaptation bounds Shorten reads, Rice widths, predictor dimensions, PCM growth and block changes, preserving unshifted predictor history across blocks. EOF and unsupported inputs return failure instead of looping or leaking. Shift 32 represents a zero block. The decoder retains signed/unsigned 8/16-bit PCM and up to two interleaved channels; the native mixer preserves stereo channels and frame duration. Every actual recording matches the pinned imported decoder's PCM exactly. The final I194 recording starts beyond 256 MiB, requiring the HRES offset mask to preserve bits 28–30 while retaining bit 31 as the external-resource flag.

Voice requests decode every segment before acceptance. A temporary owned queue commits only after all segments succeed, so missing or undecodable segments cannot suppress text or leave partial utterances queued. The mixer owns each active PCM stream; abort clears both active playback and pending segments. Current speech identifiers are initialized and cleared on completion. Saved voice flags are revalidated before speech layout, and the sample array reserves its terminating zero without changing serialization. Subtitles and dialogue choices follow the original voiced/unvoiced rules. Zero speech volume, mute, missing voices and inaudible distance return failure for text fallback; the mixer applies live speech gain once, independently of distance and SFX/music. Startup clears the hidden forced mute persisted by older unvoiced releases. Simulation timing, RNG, world rules and save chunks are unchanged.

`tools/package_complete.py` includes the verified local, user-requested voice archive in the single complete Windows ZIP. The legacy `tools/package_voices.py` remains available for older releases. Source and public engine packages exclude original media. The media manifest records the original audio's hash and copyright scope; the engine never downloads media itself.

## Display layout and live widescreen switching

`DisplayMode` and `DisplayLayout` define the classic and wide layouts independently of physical window dimensions. Widescreen adds 214 logical pixels to the map width, retains the 480-pixel screen height and moves the original sidebar right by 214 pixels. Frame artwork repeats a 32-pixel section over the new map space while retaining the original corners and sidebar ends. Compressed buttons share the inherited panel rectangle for hit testing, drawing, invalidation and cursor restoration; no button subclass retains a separate copy. Both sidebar control panels, indicators and hit regions move together; the status line expands with the map. The camera preserves its world-space center, and rendering, speech placement, cursor text and map input use the active dimensions. The original display-object limit is 100 in classic mode and 150 in wide mode; simulation activation distances remain unchanged.

The `widescreen` preference lives in the user configuration and defaults to false. Options queues the requested transition from its checkbox callback. The game thread applies it after input dispatch returns, including when Options is the current modal. Nested Language, Save/Load, Credits and other dialogs still block layout transitions. Options is recentered and its decorations follow the new origin; child controls remain alive at the same local coordinates. Its obsolete saved background is discarded before subsequent redraws and closing Options repaints the game. Screen and map buffers and the SDL texture are allocated before committing; allocation or SDL failure keeps the working mode and restores the preference. The SDL window, fullscreen state, world and existing controls survive the transition. Floating windows retain their coordinates unless they must be clamped inside a smaller framebuffer. All window clips and cursor input are refreshed. Saved screen backgrounds carry dimensions and cannot be restored into a differently sized framebuffer.

Window closing sends a pointer-leave event before removing the hovered control or its focus references. This runs while the control is alive, clears visible hover text and resets the inventory hover cache so the delayed object-text timer cannot revive a closed window's tooltip. It applies to keyboard and mouse closure through the shared window lifecycle. A refused close during dragging leaves hover and focus intact.

Physical container windows have a 25 × 21 carrier control at local (119,66), beneath the original container icon. It is independent of `alternate_sidebar` and display mode. The saved `ContainerNode` owner remains the original window association and is never rewritten for this display. Only a changed carrier invalidates the control; composition restores its decoration when possession becomes neutral. A stationary hover also receives the changed English carrier tooltip. The hit rectangle matches drawing and invalidation, and clicks do not capture input. Ground and non-player containers have no marker or hover target; death containers remain unchanged. Mental windows reuse the diamond control at local (76,42), overlaying the lower-right corner of the original head illustration above the item grid. They resolve the actor from `ContainerNode::getObject()`, independently of the selected brother or active category. Their passive tooltip reads "Julian's abilities", "Phillip's abilities" or "Kevin's abilities". The marker is drawn after the head button and takes hover priority within its rectangle. Category regions elsewhere, close/scroll controls, window size and grid geometry are retained. Closing or hiding uses the same pointer-leave cleanup.

The enlarged diamond uses the existing indexed palette: ruby 132/131/129, sapphire 178/175/172 and amber 92/90/89, with gold/brown bezel colors 89/67/48. Its faceted inset and dark outline retain the original jewel design, enlarged to end immediately above the inventory view. Mental inventory windows open at (478,114), 158 × 215 in classic mode and (692,114) in widescreen, retaining their original inset over the right sidebar. ## Document page composition

Document composition passes a screen-coordinate clip to the decorated-window renderer, together with the screen-to-local offset for its temporary pixel map. A local clip can miss centered scroll/parchment decorations in widescreen and leave transparent pixels where the previous text must be erased. Each page redraw therefore reconstructs the original artwork before drawing text and images. The original-data localization probe compares forward and reverse navigation with a full independent window repaint, including wheel routing and page limits in both languages, aspect ratios and sidebar layouts.

## Complete packages and startup

The SDL window starts in borderless desktop fullscreen, covering the monitor without changing its display resolution. The title bar and Windows taskbar are covered. Alt+Enter uses SDL fullscreen transitions to switch to a resizable window and back, preserving manually selected windowed sizes, maximization and position for the session. Automatic client dimensions follow the active framebuffer (640 × 480 or 854 × 480); changes apply immediately while windowed or after leaving fullscreen. Before a mode change or entering fullscreen, the platform compares the settled windowed size with the last accepted automatic size. Fullscreen monitor dimensions never count as a manual resize. SDL synchronization accounts for asynchronous window transitions, and the accepted automatic dimensions account for desktop constraints. Mouse conversion is refreshed after size and fullscreen changes. No additional configuration is stored. Both Enter keys and both Alt keys work. The platform consumes the shortcut before delivering keyboard events to the game UI, and key-repeat events do not toggle the window again. Rendering remains letterboxed at the selected aspect ratio with nearest-neighbour sampling; mouse conversion continues through the same SDL logical presentation after either transition.

Explicit `--data-dir` takes precedence. Otherwise the engine first checks `data/` beside the executable and then beside its containing directory, supporting both a flat layout and `bin/` plus sibling `data/`. An existing bundled path is authoritative even if incomplete or damaged: normal profile validation reports the failure rather than silently using a remembered installation. Only when no bundled path exists does discovery check the saved path and legacy locations, with the Windows folder picker as a final interactive fallback.

`tools/package_complete.py` combines a Windows engine ZIP with exactly eight allowlisted files from the supported DOS profile. It verifies their baseline SHA-256 hashes before writing, produces a deterministic ZIP for identical inputs and records data provenance in `bin/package.json`. It does not execute or modify the original files. The single local release ZIP also includes the verified optional voice archive under `media/` and the matching data-free source ZIP under `source/`. Public CI uses `tools/package_release.py` to embed sources into one runtime ZIP per platform without game data. CPack engine/source ZIPs remain internal build intermediates. Source archive roots must match the runtime version; unsafe entries and game/development data are rejected before creating output. Existing release ZIPs are never overwritten.

## Definitive Edition

The first version preserves the original mechanics and runs scripts from the original `SCRIPTS.HRS`. It does not recover the authors' story-script source files. A script disassembler, assembler and editor belong to a later stage.

Original resource loading, simulation and presentation have separate source areas and platform interfaces. SAGA2 still contains its original global state and coupling between gameplay UI and simulation. New UI, replacement graphics and further DE changes should follow completion of the regression scenarios and a full playthrough, with interfaces introduced gradually around these areas.

Exploration remains the original per-world `AMAP` visited-bit array, shared by all brothers. `updateMainDisplay` marks a radius of two metatiles around the tracked actor and skips the four corners of the clamped rectangle. Viewport dimensions do not enter this rule. The widescreen development probe checkpoints the world, tests separated brother positions and metatile-boundary crossings in both modes, checks a second world and restores all brother positions/worlds, visited bits and RNG. Ground-plane coverage samples normalize the camera to its settled actor-centered position; they do not claim coverage during camera panning, terrain occlusion or elevated viewpoints.


## Persistent diagnostics

`src/platform/diagnostics.*` owns one process session outside the engine lifetime, so the audio callback and engine destructors finish before diagnostics close. Logs live under the selected user/save directory, never inside game data. Routine messages use a mutex, bounded formatting and an unbuffered file; SDL output is mirrored while preserving the original console callback. Input records omit mouse motion. World context is copied into lock-free atomics each event loop, with a routine snapshot at most once per five real seconds. Logging does not read or advance simulation time or RNG.

Fatal records use fixed storage and a preopened OS file handle, avoiding stream locks and allocation. POSIX fault signals restore and re-raise the previous disposition after the record; sanitizer builds retain ASan's own signal handlers. Windows uses `SetUnhandledExceptionFilter` and a precreated worker thread for the system DbgHelp `MiniDumpWriteDump` call with captured exception information and a ten-second wait limit. Clean shutdown restores callbacks and handlers, joins the waiting worker and releases handles. Caught startup errors also persist their reason; failures before the selected directory is usable fall back to SDL's default user directory. If logging itself fails, the original error and working game remain available.

There is no promise of capture after forced process termination, storage failure or severe process corruption. Logs contain local paths and actions and are only shared manually. At startup, matching session logs are pruned to nine older files and dumps to three older files. The current routine log is capped at 8 MiB, allowing one final limit marker and uncapped fatal records. Dumps are created only for a crash and are outside the routine-log cap.

Version 0.1.34 also makes motion retirement idempotent while a task awaits deferred deletion. `Actor::die()` can retire the death motion during its original script callback; the animation dispatcher then tries to retire it again. The second call now returns before touching the owner, consuming RNG, waking a thread or enqueueing a second deletion. The first removal retains its original behavior and save representation.


Automatic overflow storage belongs to the receiving actor's physical drop action. Original receive scripts and the main inventory have priority; only a shortage of ready slots enables traversal, only for living player brothers. An internal breadth-first search orders physical children by row, column and object ID, revalidates the recipient/ancestor chain before each attempt and excludes locked branches and the incoming container's subtree. Trials use original merging or a drop to an explicit slot, avoiding the generic insertion fallback through parents. A failed trial continues only if the source prototype, movement and object data are unchanged, ignoring native sibling relinking. Script changes stop routing. Overflowing merged quantities use an empty slot instead of the original truncating merge. Successful moves retain existing object/UI invalidation and save fields. Exhaustion uses the original ground-drop behavior and RNG; traversal itself makes no RNG calls. NPCs, dead actors, explicit inventory-slot drops and use actions keep their original paths.

## Player screenshots and Windows launcher

Print Screen is consumed in platform event polling before game keyboard dispatch, including in nested dialogs. Repeated key-downs are ignored. `platform/screenshots.*` writes the last presented RGBA image through SDL 3.4.18 PNG support: native framebuffer dimensions, current palette, cursor and tooltip, without desktop scaling or letterboxing. A typed result event queues a localized status message after capture; English diagnostics record the actual path and error. Test/reference PPM capture still reads the original indexed framebuffer and retains its previous bytes.

The preferred screenshot directory is executable-relative: above `bin/` in runtime packages, otherwise beside the executable. The selected user/save directory is the fallback. Canonical output checks reject game-data descendants before creating directories, and exclusive file creation prevents overwrites even across processes. Failed encodes or closes remove their partial file. Source packaging excludes screenshots.

Windows packages install a small GUI launcher named `Faery Tale Adventure II.exe` at their root, embedding the existing icon. It derives the engine path from its own Unicode module filename, forwards command-line arguments without changing their quoting, and starts `bin/fta2-ce.exe` without a console. The launcher waits for the child and returns its exit code; it does not load SDL or original data itself. Native Windows relocation, icon and argument-forwarding checks are required before release. A root EXE was selected after a relative Shell Link failed to display the game icon reliably before first launch.

## Player package contents

Manual release requests resolve the selected CMake version or an explicit tag to
one commit before building. Existing tags select their original source commit;
missing matching tags are created only after all platform builds and package
audits pass. The reusable desktop workflow accepts that source commit, and the
publication job checks out the same commit. Branch pushes retain ordinary CI;
tag pushes additionally start automatic publication. Public releases remain
development-alpha prereleases with no original game data.

Runtime installation uses a common `bin/`, `licenses/`, `source/` layout, with shared SDL libraries under `lib/` on Linux/macOS. Each platform installs one root launcher and `START-HERE.txt`. Unix launchers resolve their own directory, quote paths and forward arguments with `exec`; they do not depend on the caller's working directory. `tools/package_release.py` validates an explicit player-file allowlist before adding the source ZIP. Loose desktop icons, headers, static/debug libraries, development executables and documentation are rejected. CMake no longer installs developer README/AGENTS files, docs, localization workflow, research records, complete third-party development history or loose Windows icon copies. These remain in the matching data-free source ZIP. Complete local Windows releases add exactly eight verified DOS inputs under `data/`, one verified English archive under `media/`, the source ZIP under `source/`, and `START-HERE.txt`. `bin/package.json` consolidates file/source/voice hashes and original-data copyright notices; redundant voice and source README manifests are omitted. Existing release ZIPs are preserved.


## Community Edition identity and About

The executable and package identifier is `fta2-ce`. Window titles, CLI help/version and player notices use **Faery Tale Adventure II: Community Edition**. Earlier release archives keep their original names; historical evidence retains its original contents. The old profile identifier remains only as a migration lookup: the first default-profile launch copies regular `fta2.NNN` saves and then `config.ini`, skips existing files and links, rejects game-data descendants and leaves the old profile intact. Extracted resources are regenerated rather than copied. Explicit save directories do not migrate.

A palette-drawn 13-pixel information circle sits at the right end of the map status strip in both aspects and sidebar panels. The status text extent reserves its space. Its localized tooltip opens an independent decorated modal showing the product name, Community Edition, Dominik Hladík (2026), `FTA2_VERSION` from CMake and development-alpha status. Close, Enter and Escape restore the parent. Existing game fonts and decorations are reused; the author name explicitly binds the accented bitmap font in English too. The integration matrix exercises all four languages, both aspects, sidebar layouts and individual/group panels. Reference comparison remains strict unless `--allow-about-icon` is explicitly supplied; that option permits differences only inside the exact new circle, while comparing all simulation checkpoints and original save chunks normally.
